# Documentation development

Use the Node runtime in `.node-version`, npm, and uv. JavaScript dependencies and the
standalone Python extraction environment are locked independently of the ML workspace.

```bash
npm --prefix docs ci
npm --prefix docs run setup:python
npm --prefix docs run dev
```

The authoring server uses the configured documentation prefix. Full-text search is
generated by the static build, not the live authoring server.

```bash
npm --prefix docs run check
npm --prefix docs run build
npm --prefix docs run preview
```

The Python environment contains static Griffe analysis and lightweight CLI dependencies,
not PyTorch, Lightning, GPU tools, or optional backends. Griffe runtime inspection is disabled.
Do not use this extraction environment to train models.

`build:versioned` and `build:changelog` build individual publication targets. The
default build assembles a local-only preview of both. It has a development fallback,
not copied production release archives, and cannot be used as a publication candidate.

For the additional acceptance gates:

```bash
npm --prefix docs run setup:browser
npm --prefix docs run test:api
npm --prefix docs run test:gates
npm --prefix docs run test:browser
```

Browser tests retain desktop/mobile dark/light screenshots, accessibility reports,
and failure traces in `test-results/` and `playwright-report/`. Temporary API/content/
media fixtures are removed and clean outputs rebuilt before publication. See
[editorial updates](changelog.md), [authentic CLI extraction](cli-extraction.md), and
[archive-safe deployment and future hosting migration](publication.md).

Configuration inputs: `DOCS_SITE` (origin), `DOCS_MOUNT` (deployment path), `DOCS_VERSION`
(`main`, `dev`, or a stable tag), `DOCS_REVISION` (full checked-out commit), and `DOCS_TARGET`
(`versioned` or `changelog`). Defaults keep the existing GitHub Pages project URL.

After the workflow reaches each branch and Pages is configured for Actions, pushes
to `main` update `/main/` and the global changelog; pushes to `dev` update only `/dev/`.
Both branch snapshots are labeled unreleased. Stable tags keep immutable `/vX.Y.Z/`
snapshots and advance `/latest/` only when newer. The site root stays on latest stable.
Local builds default to `dev`; use `DOCS_VERSION=main` to preview the main namespace
from your current checkout, without fetching the remote main branch.

## Migration evidence

`migration/route-map.json` maps all original authored pages and downloads. `migration/baseline.json`
records original headings/content digests and the complete published archive's Git trees.
Git tree IDs cover paths, file modes, and contents; the additional SHA-256 covers the raw tree manifest.
Re-capture against explicit refs only; this command performs no remote writes:

```bash
python3 docs/scripts/capture_baseline.py --source SOURCE_COMMIT --archive ARCHIVE_COMMIT --output /tmp/opencode/docs-baseline.json
```

Preserve every frozen release tree, including versions not listed in the initial planning discussion.
Merged page fragments without a direct equivalent fall back to their canonical destination;
specific section mappings in `route-map.json` take precedence. Never rewrite archived HTML.

The rendered-link gate checks actual HTML fragments, scripts, fonts, images/downloads,
and CSS assets without depending on external service availability. Starlight's native
404 canonical hint is not treated as a navigable content route; its real navigation
and assets are still checked. The global sitemap includes the stable alias's sitemap;
tag publication does not replace the main-published changelog sitemap/content.
