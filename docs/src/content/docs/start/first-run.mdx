---
title: Your first CPU run
description: Discover, resolve, build, and train the synthetic autoencoder for one epoch on CPU.
---

**Goal:** complete a small reconstruction experiment and inspect real results.
**Prerequisites:** [NexuML with the base library installed](/start/install/), an activated
environment, and a writable working directory. No GPU, dataset download, checkout,
or optional training/data backend is needed. [Studio](/studio/#first-training-run)
offers the same example without CLI use.

## 1. Discover the recipe

```bash
nexuml registry list scenarios
```

Find `synthetic-linear-ae-reconstruction`. This is the **registered recipe key**,
not a file path. Its Python recipe composes synthetic vectors, a linear encoder/decoder,
reconstruction loss, and evaluation. Data is generated locally.

## 2. Resolve an explicit configuration

```bash
nexuml resolve synthetic-linear-ae-reconstruction --output configs/first-run.yaml
```

Expect `Resolved config saved to configs/first-run.yaml`. Open that file: it contains
validated parameters and stable component identities, not live modules. Resolution
also compiles the graph; it does not train it.

The configuration's scenario name is `synthetic_linear_ae_reconstruction`.
The recipe key, scenario name, and chosen filename need not be identical.
The recipe's normal epoch/device defaults remain in the resolved file; the next
training command explicitly overrides them for this run only.

## 3. Build the saved pipeline

```bash
nexuml build configs/first-run.yaml
```

Expect `Pipeline compiled successfully!`, stages `Encoder`, `Decoder`, `Loss`,
the loss key `reconstruction_loss`, and reported input sizes. The compiler restores
typed definitions and checks their TensorDict routing with shape propagation.
The vectors have 128 features; the encoder produces an 8-value latent representation,
and the decoder reconstructs 128 features.

`build` reports the summary above, not a guaranteed per-layer parameter table.
Shapes/parameters can also be inspected through the compiled pipeline and configured
[diagram export](/explanation/diagrams/). This recipe has **no configured diagram**,
so this command does not create one.

## 4. Train for one CPU epoch

```bash
nexuml train --config configs/first-run.yaml --max-epochs 1 \
  -O training.accelerator=cpu -O training.devices=1
```

The override table should show `cpu` and `1`. Lightning runs fit, validation,
post-train fitting where needed, and test. Expect the one-epoch stopping message,
validation/test loss output, then `Execution finished: succeeded` and test results.
A one-epoch run proves the workflow, not model convergence or useful reconstruction quality.

## Inspect what was produced

- `configs/first-run.yaml` is the explicit, durable configuration artifact. CLI overrides
  do not rewrite it; preserve the command with your results.
- Metrics are printed in the terminal. The synthetic recipe does not configure
  TensorBoard, MLflow, a model-package export, or a Mermaid diagram.
- The session's default root is `.experiments/`, honoring `NEXUML_LOGS_ROOT`.
  Lightning can create its default checkpoint there, but do not assume a filename,
  a best/last policy, or an artifact layout across installations. To find files that
  actually exist in the default location:

  ```bash
  python -c "import os; from pathlib import Path; root = Path(os.environ.get('NEXUML_LOGS_ROOT', '.')) / '.experiments'; print(root.resolve()); print('\n'.join(str(p) for p in root.rglob('*') if p.is_file()))"
  ```

For repeatable checkpoint selection, configure [checkpoints](/how-to/checkpoints/);
for persisted curves, configure [tracking](/how-to/tracking/). Neither is required
for this first successful run.
