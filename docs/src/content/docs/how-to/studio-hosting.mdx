---
title: Host Studio behind an authenticated proxy
description: Preserve origin, private-header, API isolation, and process-ownership boundaries for trusted operators.
---

**Goal:** expose Studio through an existing authenticated HTTPS reverse proxy.
**Prerequisites:** a working [local Studio](/studio/), an operator-managed proxy/firewall,
and trusted users. Local mode needs no proxy/account. This is **trusted-operator hosting,
not public or multi-tenant SaaS**: admitted users can obtain the runtime credential and
execute local Python. Studio adds no login system and does not configure NetBird.

## Create a separate proxy credential

Never reuse the Python API token:

```sh
umask 077
python -c 'import secrets; print(secrets.token_urlsafe(32))' > "$HOME/.nexuml-studio-proxy-token"
nexuml-studio --port 3000 --public-origin https://studio.example \
  --proxy-token-file "$HOME/.nexuml-studio-proxy-token" --no-open /path/to/work
```

Use at least 32 random bytes. Keep the file outside the working directory, mode 600 on
POSIX/restricted ACL on Windows, out of version control, arguments, URLs, logs, and `.env`.
`NEXUML_STUDIO_PUBLIC_ORIGIN`, `NEXUML_STUDIO_HOST`, and
`NEXUML_STUDIO_PROXY_TOKEN_FILE` supply equivalent settings; CLI flags win.

The listener stays on **127.0.0.1** even when hosted. A non-loopback bind needs explicit
`--host` with an IPv4 address, public origin, and proxy credential, and emits a warning.
The public origin must be exact HTTPS without credentials, trailing slash, path, query,
or fragment. The Python API stays loopback-only; its allowed origin remains the
**local UI origin**, even in attach mode.

## Configure the existing proxy

- One `/` target to the **UI port**, **Pass Host Header enabled**, HTTPS, WebSocket
  forwarding, and authentication/access restrictions for trusted operators.
- **After authentication, overwrite** `X-NexuML-Studio-Proxy` with the private credential
  on every upstream HTTP/WebSocket request. Never accept a client-supplied value or
  expose it in browser code, URLs, logs, responses, or forwarded diagnostics.
- If the proxy cannot inject a private header, use a restricted header-injecting target
  proxy or keep Studio local. A public origin/forwarded Host/Proto alone cannot establish trust.
- No API proxy target or externally reachable API port. Firewall any non-loopback UI
  listener to the proxy host only, not arbitrary private-network clients.

Direct hosted bootstrap/API access requires the proxy credential even with spoofed
local/public Host/Origin: there is no unauthenticated local bypass. Browser HTTP and WS/WSS
use same-origin `/api/v1`. Next forwards to the runtime-selected loopback API, preserving
bearer/first-frame authentication, rewriting upstream Host/Origin, and stripping cookies,
forwarded metadata, and the proxy credential. Bootstrap never exposes the private API URL.

## Verify and operate

Open the exact authenticated public origin, complete the [synthetic first run](/studio/#first-training-run),
and inspect real Metrics/Logs/Artifacts. Confirm WebSocket observations work, unauthenticated
proxy access is denied, and the API port is not externally reachable. Keep evidence of
actual proxy policy rather than treating an open page as proof of isolation.

Keep the launcher terminal running. Ctrl-C stops Studio and confirmed owned local work;
closing the browser only detaches. An attached API remains caller-owned. Remote cancellation,
restart ownership, and download limits remain the [local API contract](/how-to/local-api/#operation-lifecycle-and-limits),
not a promise that stopping a UI or Ray driver stops workers.

If bootstrap/observations fail, check preserved Host, exact HTTPS origin, overwritten private
header, and WebSocket forwarding. **Do not relax API origins or trust forwarded headers**
to bypass authentication. After use, stop the launcher; remove crash temporary directories
only after confirming services stopped. Run records remain in the configured logs root.

## Hosted development

After [contributor setup](/development/install/), start the API separately with local
`--origin http://127.0.0.1:3000`, then from `studio/`:

```sh
export NEXUML_STUDIO_ORIGIN=http://127.0.0.1:3000
export NEXUML_STUDIO_API=http://127.0.0.1:8000
export NEXUML_STUDIO_TOKEN="$(cat /private/token)"
export NEXUML_STUDIO_PUBLIC_ORIGIN=https://studio.example
export NEXUML_STUDIO_PROXY_TOKEN="$(cat "$HOME/.nexuml-studio-proxy-token")"
export NEXUML_STUDIO_HOST=127.0.0.1
npm run dev -- --hostname "$NEXUML_STUDIO_HOST" --port 3000
```

Development requires the same external restrictions. HMR allows only loopback and the
configured public hostname, not a wildcard. Public origin/API port are runtime settings,
not a public API URL baked into the build. Do not dump the process environment into logs.
