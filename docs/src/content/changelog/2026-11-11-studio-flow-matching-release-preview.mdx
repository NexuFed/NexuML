**Release preview — not yet published.** These notes describe the planned v0.2.3
release, not confirmation that its packages or container image are available.
The previous production release remains v0.2.1. Version 0.2.2 reached TestPyPI
and npm candidate publication, but its original CI artifacts expired before
production publication. A fresh v0.2.3 candidate will use a new tag after merge
and successful validation; the old tag will not be deleted or moved.

## Local Studio workbench

- Author pipelines through a graph-first interface with component discovery,
  property editing, routing, and stage containers.
- Run validation, model construction, training, and export through the selected
  installed Python runtime rather than in the browser.
- Inspect live metrics, logs, artifacts, and resolved run configuration.
- Keep graph layout in a separate sidecar while YAML remains the executable
  scenario format.
- Install Studio independently as `@nexufed/nexuml-studio`. Package acceptance
  covers Linux project and isolated-tool installations; macOS and Windows remain
  unverified.

## Execution and component contracts

Backend discovery, resource discovery, preflight checks, and dispatch are shared
across Python, CLI, the local API, and Studio. Execution uses explicit `type`,
`version`, and `params` definitions with launch settings fixed at submission.
Native component input/output contracts replace custom schema extensions.
The local API and authenticated Studio hosting make runtime ownership explicit.

## Flow matching

Linear probability paths, time-conditioned vector fields, Euler integration, and
a flow-matching loss support continuous generative models. Synthetic and MNIST
scenarios include a time-conditioned U-Net, sample visualization, and integration
trajectories during evaluation.

## Documentation and distribution

- Astro Starlight documentation adds task-oriented navigation, references, and
  this global changelog, with separate main and development snapshots.
- Stable Git tags select Python and Studio package versions before CI builds and
  tests; manual version-bump commits are no longer required.
- Package publication reuses the exact tested artifacts and requires successful
  TestPyPI verification. Studio candidates publish to npm `next` before the exact
  version is promoted to `latest` on GitHub Release publication.
- The Docker build and publication job uses GitHub-hosted `ubuntu-latest`, while
  source GPU tests remain on `ika-runner-gpu`. Image verification precedes upload.
- Container tags use exact NexuML/CUDA versions, a per-CUDA `latest` alias, and
  `edge` for main. Older release builds cannot move the stable alias backward.

## Migration notes

Execution configuration no longer accepts `execution.kind` or `target.kind`.
Use a registered backend identity with `type`, `version`, and placement settings
in `params`. The local API uses interface major **3**: Studio and backend packages
must support that interface; matching package versions alone are not sufficient.

Python 3.12 or newer remains required. Package publication requires an existing
stable `vX.Y.Z` tag and its original successful tag-CI candidate; branch artifacts
and replacement builds are not release inputs.
