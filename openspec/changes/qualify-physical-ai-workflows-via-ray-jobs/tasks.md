# Tasks

Authority: [proposal.md](proposal.md), [design.md](design.md), the four adjacent capability specs and [verification-matrix.md](verification-matrix.md). Every box below is implementation or execution work and starts unchecked. Specification validation is not execution acceptance.

All application/native/browser/SDK acceptance runs use this branch's SDK Jobs functionality ported into registered `ray-jobs-sdk` on `pool_gpu_workers`, never DGX or a separate CPU-worker pool. Each job retains the default one-GPU reservation, including CPU control workloads. Local static/hermetic checks are CPU-only with CUDA disabled and do not launch acceptance workloads. Missing remote resources block the affected gate, not independent source/static work, and never authorize a local GPU fallback. Campaign concurrency is at most four in-flight independent jobs, further limited by qualified capacity; pending/setup jobs occupy slots and dependent native stages remain sequential. Required blocked rows cannot be silently waived. The user explicitly authorized rebasing onto `dev` and preserving SDK behavior within its execution structure; no second legacy execution schema is allowed.
